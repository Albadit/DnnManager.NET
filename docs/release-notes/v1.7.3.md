# DNN Manager 1.7.3

**One database, live databases at a glance.** DNN Manager keeps everything it saves in one SQLite file instead of JSON files, and Host project shows whether each folder's database is live.

## Highlights

### Your data in one database
- The settings, the workspace, how each project was installed, which sites are kept warm and the saved DNN versions are now in one SQLite file, `Documents\DnnManager\dnnmanager.db`: one row per value, every change written whole or not at all. Close DNN Manager and open it in any SQLite browser to look inside.
- Settings are now changed in the app only. The one setting that had no field, the IIS features DNN Manager checks, now has **Edit…** on **Settings → IIS**: add or remove a feature, or go back to the defaults.
- Besides `dnnmanager.db`, `Documents\DnnManager` holds only `backups`, `deployments`, `logs` and `packages`.

### See which databases are live on Host project
- Each folder shows its database next to its IIS site: **DB: Live** in green, **DB: Offline** in red when its server doesn't answer, **DB: not created** when the server has no such database yet, or **no database** when `web.config` names none.
- It is checked with the folder's own `web.config` connection, the same way the Projects table's SQL column does, right after the list appears. Hover over it to see which database it is and what the server said.
- The IIS and database texts line up in every row.

### DNN versions ready at every start
- When DNN Manager starts, it gets each repository's DNN versions from GitHub and saves them in the database, even when **Keep downloaded DNN install packages** is off. Offline, **New project** offers the versions from the last start.
- The Refresh button next to **Version** is gone. If GitHub can't be reached, it is asked again the next time you open **New project**.

## Other changes
- Keep warm works the same way for every site, as set in **Settings → Projects → Keep warm**.
- **Reset settings to defaults** no longer keeps a copy of your settings, so **Clean up data** has no *Settings copies* entry any more.
- When the settings can't be used at start, you choose **Try again**, **Reset to defaults** or **Exit**.

## Upgrading
Install over 1.7.2 as usual. **Your settings start from their defaults:** what earlier versions saved isn't read.
- Set your settings again in the app: Settings, Customize Layout, Keyboard shortcuts and the Projects table's columns. Switch keep warm on again for your sites.
- A keep-warm interval or pages of a site's own, set by hand in `state\keep-warm.json`, aren't used any more. Every site follows **Settings → Projects → Keep warm**.
- The old `settings.json`, `state` folder and `projects` folder stay in `Documents\DnnManager` untouched. Delete them once you no longer need them. Your projects, backups, logs and kept packages aren't affected.

## Tested
- All 118 fast automated tests pass, the same number as 1.7.2. New ones cover the settings and workspace as rows in the database, whether a site's database is live, and the DNN version list saved without kept packages. The tests for moving settings from older files are gone with that code.
