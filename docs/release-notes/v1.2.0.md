# DNN Manager 1.2.0

**DNN Manager gets a Windows installer.** Your settings and project backups live in your **Documents** folder, separate from the program and your sites, so updating, reinstalling or uninstalling the app never touches them.

## Highlights

### Windows installer
- `DnnManagerSetup-1.2.0-x64.exe` (recommended) installs for your user only, without administrator rights, into `%LOCALAPPDATA%\Programs\DnnManager`. You can pick another folder.
- Adds a Start menu shortcut, and a desktop shortcut if you tick it.
- Shows up in **Settings → Apps → Installed apps**, where you can uninstall it.
- If DNN Manager is already installed, Setup lets you choose **Repair**, **Update** or **Uninstall**.
- Asks you to close DNN Manager first if it's running.
- `/ALLUSERS` installs for all users into Program Files instead. `/SILENT` and `/VERYSILENT` work for unattended installs.
- Prefer no install? `DnnManager-1.2.0-x64.exe` is the portable exe - run it from any folder. Both are self-contained: you don't need to install .NET. Windows 10 or 11 (x64).

### Everything in one place: `Documents\DnnManager`
- Your settings, backups and logs live together, apart from the program and your sites:
  ```text
  Documents\DnnManager\
  ├── settings.json        your settings
  ├── docker-compose.yml   the shared SQL Server container
  ├── backups\
  │   ├── <project>\       that project's backups, one dated folder each
  │   │   └── <project>_<date>\   <project>.zip (site) and / or <project>.bacpac (database)
  │   └── settings.*.json  copies of settings.json, made before upgrades or resets
  └── logs\                the activity log, one file per day (kept 30 days)
  ```
- Backups are kept when a project is removed, and **New project → From a project backup** also lists removed projects' backups.

### Settings that can't break the app
- At startup, invalid JSON or a value that isn't allowed (e.g. a port above 65535) opens a dialog that says what's wrong - **Try again**, **Open file**, **Reset to defaults** (keeping the old file in `backups\`) or **Exit**. Missing keys are filled in with their defaults.
- `settings.json` has a `version`: an older file is backed up and upgraded, and a file from a newer DNN Manager is refused rather than overwritten.

## Other changes
- Exporting a site leaves out everything the project's `_backup.filter` lists (the Azure App Service backup format) - caches, search indexes, logs. The activity log shows what was left out.
- The **Settings** page saves each change once it is valid (no more Save and Revert buttons), and has **Open settings.json** and **Open settings folder**.
- The project menu's **Open 01_backup folder** is now **Open backups folder**, and **Export to another folder…** is gone - every export goes to the backups folder.

## Upgrading
- Settings are now in `Documents\DnnManager\settings.json`, in a new format. Start the new `dnnmgr.exe` once from the folder of the old one and its `appsettings.json` and `docker-compose.yml` are carried over (the originals are left in place). If you install the new version elsewhere, copy the old `appsettings.json` to `Documents\DnnManager\settings.json` before the first start - it is converted automatically.
- `DNNMGR_DnnManager__*` environment variables still override settings, with the same names.
- Project backups are no longer kept in each project's `01_backup` folder. Move the dated backup folders you want to keep from `<project>\01_backup\` to `Documents\DnnManager\backups\<project>\`, then delete `01_backup` - a site export now includes it.
