# DNN Manager 1.6.0

**See what a site really is.** A site's Details now read IIS, its folder, `web.config`, `bin` and its database, and mark every problem they find. The Output tab shows each operation as a pipeline of stages.

## Highlights

### Details that show the real site
- Click a site's name to open its **Details**: **General · IIS · DNN · Database · Advanced**. Everything is read from the site itself, not from what DNN Manager set up.
- **IIS**: bindings with their certificate and expiry date, SNI, the app pool's identity, recycling, limits and running worker processes.
- **DNN**: version from `bin` and from the database (marked when they differ), portals with their aliases, extensions by type, DNN's settings in `web.config`.
- **Database**: the connection from `web.config` (never the password), the SQL Server version and collation, recovery model, files, and DNN's counts.
- **Advanced**: `web.config` settings, the effective upload limit, whether the app pool can write to the site's folders, and assembly problems in `bin` (duplicates, redirects to a version that isn't there, missing references).
- Anything wrong or unusual gets an amber or red dot with the reason, and every issue is gathered in **Detected issues**.

### The Output tab is a pipeline
- The running operation on top: status, title, times and duration, counting up while it runs.
- Its stages on the left (done, warning, failed, running, still to come, skipped), with the sites kept warm below them.
- On the right every operation grouped by stage. Errors show what's behind them and what to do next, and each operation ends with **SUCCESS**, **ERROR** or **CANCELLED**.
- The log file in `Documents\DnnManager\logs` now reads as Markdown, and it also holds DNN Manager's own warnings and errors.

### Safer with your data
- **Remove…** only drops a database on this PC (the SQL container, LocalDB or a local SQL Server). A database on another server is kept, and the confirmation says so.
- Removing a site keeps an app pool that other sites still use.
- The SQL container is now reachable from this PC only, so the `sa` login isn't offered to your network.
- Restoring a `.bak` safely handles file names from someone else's backup.
- **Clean up data** and **Clear website cache** never follow a junction out of their folder.
- `web.config` is written whole or not at all.
- Questions before something that can't be undone have a red button, and **Enter** picks *Cancel*.

### Lighter while it runs
- Folder sizes are only measured while the **Size** column is shown, or for the site whose Details are open.
- Site memory is read without scanning every process on your PC every 2 seconds.
- The right-click menu opens at once, and Details only re-read what changed.
- A terminal printing a lot of output stays fast, and the Output tab keeps the newest 50 operations (the log file keeps them all).

### Settings → About
- Version, commit and build date, and whether GitHub has a newer release.
- What DNN Manager runs on (.NET, Windows, Administrator) and works with (IIS, .NET Framework, Docker).

## Other changes
- **SQL (Live / Offline)** checks each site with its own `web.config` connection, so a wrong host in Settings no longer shows running sites as offline.
- **Troubleshoot** takes the whole window like Settings, with centred content. **Reset to defaults** moved there from Settings → General.
- **Esc** closes Settings and Troubleshoot.
- Clone, Back up, Set up existing project and Import tell you when they're done; a backup's message has **Open folder**.
- **Remove…** asks once, for the site, its folder and its database together.
- The local SQL container has a **Username** field (`sa` by default), and New project has its **Database** card back.
- Links from DNN Manager open in your browser as you, not as Administrator.
- The documentation is split by reader: user guide, configuration and troubleshooting for users; development, architecture, testing, releasing and security for developers.
- Fixed: the log file stopped after **Troubleshoot → Clean up data** deleted it while DNN Manager ran.

## Upgrading
Install over 1.5.x as usual. Your settings keep their format.
- Run **Settings → Docker container → Set up docker-compose** once to make the SQL container reachable from this PC only. Your databases are kept, because they live in the data volume.
- A projects folder that is a whole drive or a system folder is now refused at start. Pick a folder of its own, such as `C:\DNN`.
- A site's own keep-warm interval and pages are gone. Every site uses **Settings → Projects → Keep warm**.

## Tested
- The Details page was checked against a real DNN 10.3.3 site and its database. It found a binding redirect to a missing assembly version and a database collation that differs from the server's.
- All 70 fast automated tests pass, up from 48. New ones cover the log file, which SQL Server addresses count as this PC, junctions during clean-up, the projects-folder and collation checks, the terminal and process memory.
