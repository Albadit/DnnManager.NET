# DNN Manager 1.7.4

**See what changed, and DNN Manager's own log.** After an update, DNN Manager shows what's new in it, and the Logs tab now shows DNN Manager's own log next to your sites' logs.

## Highlights

### What's new after an update
- After DNN Manager updates, it opens a **What's new** window with the release notes of every version since the one you had, the same text as on GitHub. They're built into DNN Manager, so they show offline too.
- It also shows after you install a newer version with Setup or a new portable exe. **What's new in this version** in the command palette opens it again.

### DNN Manager's own log on the Logs tab
- **DNN Manager** is now the first entry in the **Logs** tab's list of sites. Pick it to read DNN Manager's own log, a file a day: what each operation did, with warnings in yellow and errors in red.
- New lines appear as they are written, like a site's log. **Show DNN Manager's log** in the command palette opens it.

## Other changes
- DNN Manager looks for a newer release once, a few seconds after it starts, instead of every hour. Opening **Settings → About** or **Check for updates** in the command palette still asks right away.
- DNN Manager's log files are now named by their day without dashes, like `dnnmanager-20261004.log`.

## Upgrading
Install over 1.7.3 as usual. Your settings keep their format.
- The log files with the old name (`dnnmanager-2026-10-04.log`) are deleted when 1.7.4 first starts.

## Tested
- All 128 fast automated tests pass, up from 118. New ones cover the release notes What's new shows, DNN Manager's own log on the Logs tab, and the log file's new name.
