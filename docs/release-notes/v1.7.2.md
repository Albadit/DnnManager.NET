# DNN Manager 1.7.2

**Change a project, ship it live.** Rename a project, change its host names, app pool or database connection after it was set up, and export it as a package for the live server. Setup now always installs the newest release.

## Highlights

### Edit a project
- Each tab of a project's **Details** has Edit buttons: **Rename…** on *General*, **Edit host names…** and **Edit app pool…** on *IIS*, **Change connection…** on *Database*. They are in the command palette too, and **Rename…** is on the right-click menu.
- **Rename…** renames the IIS site, its app pool and the project's folder. If you like, it also changes the host name (`shop.dnndev.me` → `store.dnndev.me`) with DNN's site alias, and the database named like the project. The site is stopped meanwhile and started again.
- **Edit host names…** changes, adds or removes the host names and ports the site answers on. DNN's site aliases follow; https bindings stay as they are.
- **Edit app pool…** sets the .NET CLR version, pipeline mode, 32-bit, identity, idle time-out and start mode.
- **Change connection…** points `web.config` at another database, server or sign-in, with **Test connection** first.
- Each runs on the **Output** tab like any operation: **Cancel** puts back what it changed, and a step that fails takes back the ones before it.

### Export for deployment
- **Export ▸ For deployment…** (right-click menu, the **⋮** on Details, or the command palette) asks for the live domain, whether the site uses HTTPS, and optionally the live connection string.
- It makes `Documents\DnnManager\deployments\<project>_<date>\` with three files:
  - `<project>.zip`: the site's files without `.git`, editor folders, `node_modules`, DNN's logs, cache and search index. Its `web.config` has the live connection string (or a placeholder), debug off, and the HTTPS redirect rules DNN Manager switched off back on.
  - `<project>.bacpac`: the database with the live domain as its site alias.
  - `DEPLOY.txt`: the steps on the server.
- Your local site and database aren't changed. The database is changed in a temporary copy, so this needs a SQL login that can create a database.

### Setup always installs the newest version
- A new install and **Update to version X** get GitHub's newest release, and **Repair** downloads the version you have installed again. A Setup you kept never has to be replaced.
- Every download is checked against GitHub's SHA-256 and its version before it runs.
- Without internet, Setup installs the version it carries, and offers it when a download fails.

### Works without internet
- With **Keep downloaded DNN install packages** on (Settings → DNN releases), the versions of each repository are saved. Offline, **New project** offers them, and the ones marked *kept, no download* are set up as usual.
- GitHub that doesn't answer within 30 seconds counts as offline, instead of a wait of 100 seconds.

### A steadier status bar
- RAM, CPU and Disk keep their place: each is as wide as its largest value, so one figure no longer pushes the others when a number gains a digit.
- They read `RAM 0.00 GB`, `CPU 0.00%` and `Disk: --.-- GB used (limit --.-- GB)` until all three are measured, then change together.

## Other changes
- The **⋮** on Details has the whole **Export** menu, the same as the right-click menu.
- Every folder in `Documents\DnnManager` exists from the first start. **Settings → About** lists **Deployments** too, and **Open** makes a folder that isn't there.
- A DNN download that fails without internet says what to do.
- The bottom panel's header has as much room at its ends as above and below.
- Fixed: backing up the database of a site that signs in with Windows authentication exported from the local SQL container instead of the site's own database.

## Upgrading
Install over 1.7.1 as usual. Your settings keep their format.
- Which sites are kept warm is now saved in `state\keep-warm.json`, and what earlier versions saved isn't read. Switch keep warm on again for your sites, and set any interval or pages of their own again.
- Setup installs the newest release from this version's Setup on. The 1.7.1 Setup still installs the version it carries.

## Tested
- The new Setup was checked on a PC with 1.7.1 installed, built as 1.7.0: **Repair** downloaded 1.7.1 from GitHub, checked it and handed over to it. Offline, it offered to install the version it carries.
- All 118 fast automated tests pass, up from 112. New ones cover the saved version lists without internet and the `web.config` changes for the live server.
