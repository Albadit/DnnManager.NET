# DNN Manager 1.5.0

**Your sites stay fast.** Keep warm stops IIS from putting an idle DNN site to sleep, so the next page opens at once instead of after 30 seconds of DNN starting up.

## Highlights

### Keep warm
- Click the **flame** in a site's Actions (or use its right-click menu or overview) to keep that site warm while DNN Manager runs, minimized too.
- IIS shuts an idle site down after 20 minutes. DNN Manager requests DNN's built-in `/KeepAlive.aspx` before that happens: every 5 minutes, sooner for a shorter idle time-out, and not while you're using the site.
- After a recycle, crash or IIS restart it also loads the home page, so the first real page is fast too, not just DNN itself.
- Plain HTTP requests on your own PC: no browser, no mail server, no extension, nothing changed in IIS or DNN.
- It waits while the site or IIS is stopped, an operation is running, a debugger is attached or the SQL container is down. If a site keeps failing it stops trying until you press **Check now**.
- It never requests DNN's installer.
- The flame shows how it's going: warm, warming up, paused or failing. Its tooltip says what a click does: *Enable keep warm* / *Disable keep warm*.
- Defaults are in **Settings → Projects → Keep warm**; a site can have its own interval and pages on its overview.

### One database server setting
- **Settings → Database server** decides where new projects get their database: the **Local SQL container (Docker)**, **SQL Server / SQL Server Express** (Windows or SQL Server authentication) or a **LocalDB file**.
- New project no longer asks: the database is named after the project and the server is tested before anything is created.
- Database profiles and **Save as profile…** are gone.

### Troubleshoot page
- Open it with the **bug** icon next to the gear.
- **Restart** restarts DNN Manager.
- **Clean up data** deletes what you tick, each shown with its size: logs, kept DNN packages, settings copies and project backups (never ticked for you).
- **Reset to factory defaults** puts DNN Manager back as it was installed. Your projects, their IIS sites, folders and databases are never touched.

### Cancel puts everything back
- Cancelling an operation removes what it had already created, newest first: the IIS site and app pool, the database, files and folders, an edited `web.config`.
- The Output tab shows each step. Anything that can't be undone is named there.

### Test and set up, inside Settings
- The Environment page moved into **Settings**: **Docker container**, **Database server** and **IIS** each end with a **Test and set up** card.
- **Set up docker-compose**, **Set up IIS** and the other fixes are right next to the settings they use.

### Your size, your font
- **UI scale** (80-175 %) and **font size** (11-18 px) in **Settings → General**, applied at once.

### Light on resources while out of sight
- Efficiency mode now also starts when the window is covered by other windows, on another virtual desktop or behind the lock screen, not only when minimized.
- It uses Windows' own *Efficiency mode*, the leaf icon in Task Manager. Terminal shells still start at normal priority, and operations always run at full speed.

## Other changes
- **Open with…** lists your editors and each installed SQL Server Management Studio in one submenu.
- **Clone project** is now **Clone…** on a project's right-click menu.
- Long lines in the Output tab wrap at the panel's width, and copying gives them back without the breaks.
- Copy and paste are **Ctrl+C** / **Ctrl+V** and the right-click menu on every tab of the bottom panel.
- The Projects table shows the **URL** column by default, and the Actions column is tighter.
- The README is short and easier to read. The details moved to `docs/user-guide.md` and `docs/development.md`.

## Upgrading
Install over 1.4.x as usual. Your settings are upgraded on first start:
- The database profile your new projects used becomes the **database server**, and its password moves to the Windows Credential Manager.
- Other database profiles and their passwords are removed. Existing projects keep their databases.
- The new settings (keep warm, UI scale, font size) are added with their defaults.

## Tested
Keep warm was tested on real local DNN sites in IIS (20-minute idle time-out). After 27 minutes with no visitors:
- sites kept warm answered in **14-71 ms**
- the same kind of sites not kept warm needed **2-32 s**, and up to 76 s on their first cold start that morning

All 48 automated tests pass. They include:
- keep warm with several sites side by side, switching on twice, a site going down and coming back, and an app restart
- the automatic DNN install end to end on DNN 10.3.3 with IIS Express
