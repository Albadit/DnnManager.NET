# DNN Manager 1.7.6

**Keeps running when you close it.** Closing the window now hides DNN Manager to the notification area, where operations, terminals and keep warm go on - Setup no longer asks you to close it first, and the command palette opens any Settings category directly.

## Highlights

### Keep running in the background
- Closing the window - its **✕** or **Alt+F4** - hides it, and DNN Manager keeps running: a running operation goes on, the terminals keep their shells, and your sites are still followed and kept warm.
- DNN Manager's icon in the notification area, by the clock, opens the window again with a click, as you left it. Right-click it for **Open DNN Manager** and **Quit DNN Manager**. On Windows 11 the icon may be under the **^** until you drag it out.
- Starting DNN Manager again from the Start menu also brings the hidden window back.
- The first close after each start says so in a Windows notification, and an operation that fails while the window is hidden says so in one too.
- **Quit DNN Manager** is in the command palette as well. As with any quit, it asks first while an operation runs, and the window comes back for the question.
- On by default. Turn **Keep DNN Manager running when you close the window** off in **Settings → General** to have closing quit again.

### Settings from the command palette
- The command palette has a **Settings** group: **Settings: General**, **Projects**, **DNN releases**, **Database server**, **Docker container**, **IIS**, **Keyboard shortcuts** and **About** open Settings on that category, or switch to it while Settings is open. **Open Settings** itself stays under **Pages**.
- Like every command, each can have a shortcut in **Settings → Keyboard shortcuts**.

### Setup without "close DNN Manager first"
- Setup opens even while DNN Manager is running. When DNN Manager is installed, its first page has a button for each choice: **Update to X** (when there is a newer release), **Repair** and **Uninstall**.
- When one is done, Setup comes back to that page - with *Repair finished.* or *Update finished.* - or, after an uninstall, to a new install's first page. **Close** ends it.
- Just before Repair or Update replace its files, and once you confirm an uninstall, Setup closes a running DNN Manager without asking - a running operation is cancelled, and what you were doing is kept for the next start. After Repair or Update it starts again.

## Other changes
- Saving resources while the window can't be seen is always on, and no longer a setting. It only pauses what nobody can see - animations, this PC's figures, redrawing terminals, following a log - and brings everything up to date as soon as the window is seen again. A window hidden to the notification area counts as not seen.
- The terminal is always on: the Terminal tab, **New terminal** and **Open in terminal** are always there. **Settings → General** keeps its shell and font.
- DNN Manager moved to [github.com/Albadit/DnnManager.NET](https://github.com/Albadit/DnnManager.NET). Updates, the installer's links and **Settings → About** point there, and Windows' installed apps list Albadit as the publisher.

## Upgrading
Install over 1.7.5 as usual. Your settings keep their format.
- Closing the window no longer quits DNN Manager - quit from its icon in the notification area or the command palette, or turn the setting off in **Settings → General**.
- **Save resources while the window can't be seen** is gone from **Settings → General**; it is always on now.
- **Enable the terminal** is gone from **Settings → General**. If you had switched the terminal off, it is back.
- 1.7.5 finds this update at its old address: GitHub sends it on to the new one.
- An older DNN Manager can't be asked to quit: when one is running, Setup ends it, after Windows asks for administrator rights.

## Tested
