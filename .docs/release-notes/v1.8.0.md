# DNN Manager 1.8.0

**Your sites work without internet.** DNN Manager keeps your sites' host names in the Windows hosts file, so `*.dnndev.me` and your own domains open on this PC offline too. New project checks the host name and the database before it starts, and the Projects page stays responsive with many sites.

## Highlights

### Sites that open offline
- `*.dnndev.me` used to be found through DNS on the internet: without internet the browser couldn't find a site, although IIS and DNN were running. Now every site's host name is in `C:\Windows\System32\drivers\etc\hosts`, so it opens offline too, also after a restart of the PC with DNN Manager closed.
- DNN Manager keeps its own block in that file, between two marker lines. The rest of the file stays as it is, and a name you map yourself keeps your line.
- The lines follow your sites: **New project**, **Rename…**, **Edit host names…** and **Remove…** update them, and so does a site made in IIS Manager.
- See the file itself in the bottom panel's **Logs** tab: **DNN Manager** → **Hosts file**, shown again whenever it changes.
- If the hosts file can't be written (read-only, or blocked by security software), a warning says so.

### Your own domains
- A site bound to a host name of your own, such as `shop.test`, `klant.local` or `www.customer.nl`, opens on this PC without editing the hosts file.
- **New project**'s hint under **Host name** tells you the name goes into the hosts file, and that a real domain then opens your local site instead of the live one.

### New project checks before it starts
- A host name and port that another IIS site already answers on are refused as you type, with the site's name. Before, the setup went ahead, and the new site couldn't start.
- The database server is asked whether the database is free: *Checking…*, *is free*, *already exists*, or why it can't be asked. A server that doesn't answer is asked again every 10 seconds, so starting the SQL container is noticed by itself.
- **Create project** waits until both checks pass, instead of the setup stopping after DNN has been downloaded. With **Manual DNN setup** an existing database is still allowed.

### A responsive Projects page with many sites
- The search filters as you type: about 7 ms a key instead of 230 ms with 18 sites, and 600 ms with 50.
- The table only builds the rows on screen and still scrolls smoothly by pixels. With 50 sites it shows and sorts in about half the time.
- Programs that follow other windows, such as Windows' text input, PowerToys and screen readers, no longer slow the table down. They made a sort or the table coming back take up to half a second. A screen reader now reads each row by its project, for example "shop, Running, http://shop.dnndev.me".
- A site's overview opens faster: only the tab you see is built.
- Less work in the background: after an operation only that site's folder is measured again for the **Size** column, and a stopped SQL container is asked once every 10 seconds instead of once per site.

## Other changes
- **Settings → General → Play animations**: switch it off and the panel, sidebar, toasts, menus and switches change at once, and nothing pulses. Animations are also off while Windows' animation effects are off.
- In the **Output** tab, click a stage and the log scrolls to it.
- The bottom panel slides open whatever opens it, such as a toast's **Show output**, **View logs** or a new terminal, as it does with its button.
- Toasts appear at the bottom right of the page, above the bottom panel, no longer over the **Output** tab or a terminal.
- The worker processes' CPU and memory are read with less work every 2 seconds.

## Upgrading
Install over 1.7.x as usual. Your settings keep their format.
- At its first start DNN Manager adds its block of host names to `C:\Windows\System32\drivers\etc\hosts`. The lines stay when you close DNN Manager.
- A site bound to a real domain now opens the local site on this PC instead of the live one. To see the live site again, take that host name off the site with **Edit host names…**, or remove the site.

## Tested
- With the network adapters switched off, on three real DNN sites in IIS, a site made while offline and a `.test` domain: each opened in Edge and Chrome, with its pages and static files. The sites also answered with DNN Manager closed, after it was started again, and after `iisreset`. Restarting the PC wasn't tested.
- With 19 real sites, the Projects page was profiled while in use, before and after: the UI Automation work behind the stalls no longer shows up.
- With 19, 50, 100 and 200 simulated sites and a program following the window's UI Automation, the search takes 7-9 ms a key at every size. Memory stayed flat over a 6-minute run.
- All 220 fast automated tests pass, up from 197. New ones cover the hosts file block (the rest of the file kept byte for byte, your own lines left alone, custom domains), the hosts file in the **Logs** tab, refusing a host name another site has, asking a stopped SQL Server once, sampling the worker processes, and animations switched off.
