# DNN Manager 1.3.0

**DNN Manager now works more like Docker Desktop.** **Projects** is a live table that keeps itself up to date without a Refresh button. A new status bar shows IIS and your PC's resources, and a terminal panel puts the activity log next to real terminals. Settings has its own page and applies without a restart, and all the controls now share one look.

## Highlights

### Projects is a live table
- Sites started or stopped in IIS Manager, IIS restarts and project folders added or deleted show up within seconds, without a Refresh. Your checked rows, search, sort order and scroll position stay where they were.
- **Start, stop and restart sites** from each row, or several at once with the check boxes.
- Search the table and pick its columns: live status, ports, CPU, memory, PID, disk and network I/O, database state and more.
- **Open with** lists only the editors installed on your PC: Visual Studio, VS Code, Cursor, Windsurf, Rider, IntelliJ IDEA, Sublime Text, Zed, Vim and Neovim.

### Status bar and terminal panel
- **Status bar**: whether IIS is running (with Start / Stop / Restart), this PC's RAM, CPU and disk use, and the running operation with a **Cancel** button.
- **Terminal panel**: the activity log plus real terminals (PowerShell, PowerShell 7, Command Prompt, Git Bash) with colours and tab completion. **Open in terminal** opens one in a project's folder.

### Pick a DNN version from a list
- New project lists the repository's releases, highest version first, with the latest release selected. Pre-releases are listed too, marked *(pre-release)*.
- **Keep downloaded DNN packages** (optional setting), so a version you've already downloaded installs with no new download.

### Settings and setup
- **Settings has its own page** with categories and search, and applies as soon as you **Save**, with no restart.
- **Start DNN Manager when you sign in** (Settings → General), without a UAC prompt at sign-in.
- **Environment → Set up IIS** checks the IIS Windows features and turns on the missing ones.

## Other changes
- New projects get a database named like the project (`mysite`, not `mysite_dnndev`).
- **Set up docker-compose** runs the compose file built from your settings directly, so no `docker-compose.yml` is written to disk. **Show docker-compose.yml** shows it without the SA password.
- Docker and SQL Server settings are now in separate sections, and so are their Environment cards.
- DNN versions are sorted by version number, so 9.13.x no longer sits between 10.x releases.
- One look for every control: rounded text and password boxes, one height for buttons, inputs and selects, theme-aware check boxes and radio buttons, and rounded menus.
- Light / Dark / *Use system settings* theme, a custom title bar with Snap layouts, and a compact sidebar in narrow windows.
- **Reset IIS** has been removed; restart IIS from the status bar instead.
- Fixed: imported, cloned and restored sites no longer redirect to `https://`. DNN's SSL setting is switched off in the local database, and the activity log warns you to switch it back on before that database goes live.
- Fixed: Setup now closes after you choose *Uninstall DNN Manager*.

## Upgrading
Install over 1.2.x as usual.
- **Settings are upgraded automatically** on first start. The old `settings.json` is backed up to `Documents\DnnManager\backups\` first, and the SA password in it is now stored encrypted.
- **The program is renamed** to `dnnmanager.exe`. If you pinned DNN Manager to the taskbar, pin it again. Environment variables now start with `DNNMANAGER_` (it was `DNNMGR_`).
- **The SQL Server container's Docker Compose project is renamed** from `dnn-shared` to `dnn-mssql`. Press **Environment → Set up docker-compose** once. It recreates the container under the new name, and **your databases are kept** because they live in the data volume.
