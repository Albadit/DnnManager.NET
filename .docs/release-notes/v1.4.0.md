# DNN Manager 1.4.0

**New project now installs DNN for you.** The first visit shows your new site, already set up with the host account you chose. You no longer go through DNN's installation wizard.

## Highlights

### Automatic DNN setup
- DNN Manager runs DNN's own unattended install. The Output tab shows each step: *Testing database connection → Creating project directory → Creating IIS application pool and website → Creating database → Configuring DNN → Running DNN installation → Creating portal → Creating host account → Starting website → DNN installation completed*.
- Problems are caught before anything is created: a host password DNN would silently reject, a project folder too deep for DNN's packages, or a database that can't be reached.
- DNN's install output is checked line by line, because DNN reports success even when a package fails.
- Afterwards the install template, which holds the password, and DNN's installer pages are deleted.
- **Manual DNN setup** is still available if you want to run the wizard yourself.

### Choose your database
- **Local SQL container (Docker)**, as before.
- **SQL Server / SQL Server Express**, with Windows authentication (the site's app pool gets its own login and owns the database) or SQL Server authentication.
- **SQL Server Express LocalDB (file)**: the package's own `App_Data\Database.mdf`.
- **Test connection** checks the server, the sign-in, the SQL Server version and the database permissions. **Save as profile…** keeps a connection for next time.

### DNN defaults
- **Settings → Projects → DNN defaults** sets the host username and password, e-mail, website name, language and site template for new projects.
- Passwords are kept in the **Windows Credential Manager**. They never appear in `settings.json`, the Output tab or the log file.

### Site overview with tabs
- **General · IIS · DNN · Database · Advanced**.
- The **DNN** tab shows how the site was installed, its version, the host account, and the portals with their aliases. **Change host password…** sets a new host password.
- The **Database** tab shows the connection details and has **Test connection**.

### Bottom panel like VS Code
- **Output · Logs · Terminal** tabs.
- **Logs** shows a site's DNN logs, IIS logs and Windows events, live.
- **Ctrl+F** searches with Match Case, Whole Word and Regex.
- Maximize with **Ctrl+Shift+M**; each shell has its own icon.
- New site tools: **Clear website cache…** and **View logs**.

### Light on resources while minimized
- Animations, figures and log following pause while the window is minimized, and Windows runs the app in efficiency mode (EcoQoS) when nothing is running.
- Idle CPU while minimized is about **1/7** of before.
- Restoring the window brings everything up to date at once, without a loading screen.

## Other changes
- **Projects** lists only DNN sites in IIS.
- **Remove…** drops a project's database wherever it lives.
- The program is now **`DnnManager.exe`**. Setup replaces the old `dnnmanager.exe`.

## Upgrading
Install over 1.3.x as usual. Your settings are kept, and the new settings are added with their defaults on first start.

## Tested
The automatic install was tested end to end on a clean DNN 10.3.3 using IIS Express, with:
- LocalDB using Windows authentication
- a LocalDB database file
- a SQL Server 2022 container signed in as `sa`
- a SQL Server 2022 container with its own login
- Manual setup, which leaves DNN's wizard in place
