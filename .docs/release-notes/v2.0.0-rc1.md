# DNN Manager 2.0.0-rc1

**Push and pull your sites, also on macOS and Linux.** A new **Source Control** page compares your projects with their servers over SFTP, FTPS or FTP and pushes or pulls only the files you choose, after a review. It runs on Windows in DNN Manager, and on macOS and Linux in a new app. This is a release candidate: try it before 2.0.0.

## Highlights

### Source Control: deploy to a server, like git
- **Source Control** in the activity bar (**Ctrl+3**) connects a project to its development, staging and production servers over **SFTP** (password or private key), **FTPS** or **FTP**.
- A server is set up as in FileZilla's Site Manager: the same protocols, encryptions and logon types, in the same words. An Azure App Service connects as it does in FileZilla.
- A server compares the files with the content they last agreed on. A file changed here is yours to push, one changed on the server is yours to pull, and one changed on both sides is a conflict. Which clock is later never decides it.
- Each change has its diff, side by side or in one column. Stage the files you want, write a message, then push or pull only those, after a review of every file.
- Nothing is overwritten unseen. A file changed since the comparison stops the push or pull before anything changes. A push that fails or is cancelled puts back what it sent.
- Every push and pull is kept in the history, with each file before and after, and can be rolled back.
- Secrets and each environment's own configuration (`web.config`, `App_Data`, keys) are left out, or asked about before they are sent.

### Choose what to compare
- Opening Source Control reads nothing from a server. Choosing a server compares it, and **Ctrl+click** or **Shift+click** compares several, one after the other.
- **CHANGES** shows one server at a time, with its name beside the title to switch.
- A server can have its own **Local folder**, with **Browse…**, instead of the project's folder.
- **Settings → Source Control** sets whether the page compares by itself when it opens, how long the history keeps file versions, and what a new server starts with.

### Explorer, Search and tabs
- Icons at the top of Source Control's side bar switch between **Source Control** (**Ctrl+Shift+G**), an **Explorer** (**Ctrl+Shift+E**) of the project's files as a push sees them, and **Search** (**Ctrl+Shift+F**).
- Search can match case, whole words or a regular expression. **Replace all** shows what it will write and asks first, then keeps each file's encoding and line endings.
- Open files have tabs. Drag a tab to another place, or move the chosen one with **Ctrl+Shift+PageUp** / **PageDown**.
- Select a diff's code and copy it with **Ctrl+C** or the right-click menu. **Unified**, **Side by side** and **Whole file** are icon toggles.

### A window laid out as VS Code's
- The sidebar is now the **activity bar**: the pages as icons, with their names as tooltips.
- Beside it, the **primary side bar** holds a page's own view (**Ctrl+B** hides or shows it). The **secondary side bar** opens with **Ctrl+Alt+B**.
- Drag either side bar wider or narrower. DNN Manager keeps the widths between starts, and **Customize Layout** shows or hides each part.

### DNN Manager on macOS and Linux
- A new app runs **Source Control** on macOS (Apple Silicon and Intel), Linux (x64 and arm64) and Windows, with the same servers and history as the Windows app.
- Explorer, Search, tabs, merging a conflict and the layout above are in DNN Manager for Windows only, for now. In the new app you keep the project's or the server's version of a conflict.
- Making and running DNN sites needs IIS, which only Windows has. Those pages say so, and suggest DNN Manager in a Windows virtual machine.
- On macOS and Linux, saved passwords are encrypted with a key that only your account can read.
- The release has a package for each: `DnnManager-2.0.0-rc1-macos-arm64.zip`, `-macos-x64.zip`, `-linux-x64.tar.gz` and `-linux-arm64.tar.gz`.
- The macOS app isn't notarized by Apple. The first time, right-click **DNN Manager** and choose **Open**. On recent macOS, use **System Settings → Privacy & Security → Open Anyway**.

## Other changes
- Viewing files in Source Control reuses one connection to the server, reads each file once and reads the next few ahead, so files open quickly.
- A group's title in the changes list folds it with one click, and stays at the top while you scroll.
- The `.gitignore` written into a new site no longer leaves out files the site needs (DNN's `js/Debug`, `bin/x64`, install packages, 2sxc apps, portal themes). It now leaves out the site's `web.config` and its copies, database backups and `.env` files. Existing sites keep theirs.
- Fixed: a diff's selection was drawn a few characters off from its text.

## Upgrading
This is a pre-release. The **Update** button doesn't offer it: download it from this release's page. Install it over 1.8.x as usual. Your settings are kept, with a new **Source Control** section.
- When 2.0.0 is out, **Update** offers it to you.
- On macOS and Linux, unpack the package and start **DNN Manager**. Projects go in `~/DNN` unless you choose another folder, and **Settings → About** shows where the app keeps its data.

## Tested
- All 587 fast automated tests pass, up from 498 in 1.8.7. New ones cover Source Control against a folder standing in for the server: comparing, pushing and pulling, conflicts and merges, retries and resumed uploads, rollback, and pushes that fail or are cancelled.
- The new app's 4 automated tests pass on Windows. They cover choosing a server, which compares it and shows a file's diff; adding a server with its own local folder; the macOS and Linux encryption of saved passwords; and the default projects folder.
- The new app has not yet been run on a real Mac or Linux PC: this release candidate is for that.
