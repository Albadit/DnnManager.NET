# DNN Manager 1.8.6

**Imported sites, on your address.** Choose the host name and port of a site you import, just as for a new one. A `.bacpac` from an Azure SQL database now imports instead of stopping with a SQL error.

## Highlights

### Choose the address of an imported site
- **New project → An existing site** now shows the **IIS** card: the **Host name** and **Port** the site answers on.
- It starts as `<name>.dnndev.me` on the port from **Settings → Projects**. Change either one, or type a domain of your own such as `shop.test`. It goes into the hosts file, so the site opens without internet.
- It is checked as you type: an address that another IIS site already has is refused, and **Import project** waits until you choose another.
- DNN's site alias in the imported database follows the address you chose, so the site loads there on the first visit.
- When the import is done, the toast has **Open site**.
- The **IIS** card now sits right under **Project**, for a new site as well as an imported one.

### A .bacpac of a contained database imports
- A database with users that have a password of their own, which an Azure SQL database often has, stopped the import with *BACPAC import failed: CONTAINMENT = PARTIAL | WITH ROLLBACK IMMEDIATE; | END*. Whatever the import had done was then undone.
- DNN Manager now switches on SQL Server's *contained database authentication* for that server and imports again. The Output tab says so: *switching on 'contained database authentication'*.
- When an import fails, the message now gives SQL Server's own error (for example *Msg 12824, …*), not the last lines of the script it was running.

## Other changes
- DNN Manager now runs on .NET 10.0.14, which fixes a security issue in .NET's Brotli decoder.
- In the getting started guide, **Host name and Port** is now step 2 of the New project form, in the same order as the page.

## Upgrading
Install over 1.8.5 as usual. Your settings keep their format.
- Importing a contained database switches on *contained database authentication* on that SQL Server, and it stays on. It only matters for contained databases.

## Tested
- All 498 fast automated tests pass, up from 493. New ones cover an import on a chosen host name and port, an import without one keeping `<name>.dnndev.me`, a contained database recognised from SqlPackage's output, and the error message an import shows.
