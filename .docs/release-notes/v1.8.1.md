# DNN Manager 1.8.1

**Your projects stay out of each other's way.** Import, Clone, Host project and New project no longer touch another project's database or IIS site, and a failed operation takes back what it made. DNN Manager is also safer with its Administrator rights and works with screen readers.

## Highlights

### Each project keeps its own database and site
- Importing a zip that you exported on this PC under a new name no longer restores into the original project's database or moves its portal alias. The new project always gets a database of its own, and its `web.config` points to it.
- A name used by an IIS site that serves another folder is refused while you type, in **New project**, Clone, Import and **Host project**. Before, that site was replaced.
- **Host project** doesn't take over a database that another IIS site uses. It makes one under the project's own name.
- Clone checks everything before it copies a file. It reads the source's database from the source's own `web.config`, and stops if the local SQL Server can't be reached, rather than leaving a copy that uses the source's database. It asks before replacing a database of the clone's name (**Replace database** or **Keep it**), and the copy replaces the old one only once it is complete.
- **Remove…** keeps a database that another IIS site uses too, and says when a database couldn't be dropped.

### A failed operation leaves nothing half made
- When New project, Clone, Import or Host project fails (an offline download, an IIS error), the folder, site and database it made are taken away again, as after **Cancel**. You can use the same name straight away. Only a failed DNN installation is kept, so you can look into it.
- Quitting DNN Manager while an operation runs waits for it to stop and put back what it did.
- A DNN upgrade step that fails unexpectedly is rolled back. Before, it left the site half upgraded.
- **Restore backup** imports the database before it touches the site's files, so a failed import leaves the project as it was.

### Safer with Administrator rights
- Updates are downloaded into `%ProgramData%\DnnManager\temp`, which only administrators can change, and checked again just before they are installed. A release that GitHub lists no SHA-256 for isn't installed.
- DNN Manager starts `docker`, `dotnet`, `winget`, PowerShell 7 and Git Bash only from a copy installed for all users, which no other program you run can swap.
- Editors such as VS Code and Rider open as you, not as Administrator.
- A new site signs in to the SQL container with a login of its own instead of `sa`. A new installation makes up its own `sa` password and has no default DNN host password.
- The projects folder is limited to SYSTEM, Administrators and you.
- A password copied for SQL Server Management Studio stays out of Windows' clipboard history and cloud clipboard, and is cleared after 60 seconds.

### Screen readers and the keyboard
- Every field and icon button has a name that screen readers read out. The **Logs** tab and the terminal are read as documents, and toasts are announced.
- Error, success and warning text in the light theme, field borders and the dark theme's focus ring now have enough contrast. Windows' Contrast themes are followed.
- **Ctrl+A** ticks every row on the Projects page. The command palette (**Ctrl+Shift+P**) can choose the columns, sort the projects, and make the sidebar and the bottom panel bigger or smaller.
- **Create project** says what is still needed before it can start, for example *Still needed: a DNN version, a database.*

### Lighter while it runs
- The **Output** tab updates once a second while an operation runs, instead of ten times.
- Project files are copied four at a time, and zips are made with fast compression.
- The bottom panel's search stops after a set time instead of freezing the window on a difficult pattern.
- A LocalDB database is no longer checked every 10 seconds, which kept LocalDB running.

## Other changes
- **Settings → General → Look for a newer DNN Manager when it starts**: switch it off and only **Settings → About** asks GitHub.
- **Remove…** offers to delete the project's backups too (**Delete backups** or **Keep backups**).
- **Troubleshoot → Clean up data → Deployment packages** deletes the packages made by Export for deployment.
- The **Output** tab no longer lists the sites kept warm under *Background*: the Projects page already shows them.
- A copy of the hosts file is kept as `hosts.dnnmanager.bak`, next to it, before each change. International host names are written in punycode.
- A download that receives nothing for a minute fails instead of waiting forever.
- A day's log file stops at 50 MB, and old log files are deleted when the day changes.
- Each release on GitHub lists every file's SHA-256 in `SHA256SUMS.txt`.
- Fixed: Clone failed from a SQL Server with Windows authentication and from SQL Server Express.
- Fixed: portal aliases lost the site's port, and a DNN site with an `objectQualifier` didn't get its aliases and SSL fixed after a clone, import or Host project.
- Fixed: a failed drop or restore left the database in single-user mode. Renaming and dropping work on Azure SQL Database.
- Fixed: editing bindings lost each binding's IP address, stopping a site stopped an app pool that another site's application used, and renaming a site only in capitals failed.
- Fixed: the DNN version list missed the oldest releases.
- Fixed: Export for deployment didn't find a `Web.config` with other capitals, and a zip export failed on a file older than 1980.
- Fixed: sites sharing an app pool showed no CPU.

## Upgrading
Install over 1.8.0 as usual. Your settings keep their format.
- An existing installation keeps its `sa` and DNN host passwords. If yours is still `Admin@123`, change it in **Settings → Database server** and **Settings → Projects**.
- At its first start DNN Manager limits the projects folder (`C:\DNN`) to SYSTEM, Administrators and you. Every other account on the PC loses access to it. With many sites this can take a moment.
- `docker`, `dotnet`, `winget`, PowerShell 7 and Git Bash must be installed for all users. SqlPackage is installed again into `%ProgramData%\DnnManager\tools` the first time it is needed, and a copy in `~\.dotnet\tools` isn't used.
- Sites made before keep signing in as `sa`. New ones get a login of their own.
