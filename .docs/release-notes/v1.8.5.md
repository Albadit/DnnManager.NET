# DNN Manager 1.8.5

**The whole upgrade path is yours.** Change what any version of DNN's upgrade path needs, take a version off, and carry the path to another PC as a file. Host project is gone: websites come in through New project and Clone.

## Highlights

### Edit the whole DNN upgrade path
- **Settings → DNN releases → Edit upgrade path…** shows every version of the path, newest first, as a row you can change - not only the versions you added.
- Raise or lower what one of DNN's own versions needs (**Needs .NET Framework**, **Needs SQL Server**), or choose *No new minimum*. The tooltip of each list says what DNN's path has.
- Give any version a **Note in the upgrade plan**, and take a version off the path with its delete button, so upgrades no longer stop at it. The versions of DNN's that are taken off are listed under the path.
- **Add version** puts a new row at the top, and **Reset to DNN Manager's path** undoes every change.
- The dialog is a window you can resize: make it bigger to see more versions at once, and the notes widen with it.
- The upgrade plan says what is yours: a step to a version you added, one that skips a version you took off, and one whose minimums you changed each carry a warning, and none of them is shown as tested.

### Take the upgrade path to another PC
- **Export…** saves the path, as it is in the dialog, to a `.json` file.
- **Import…** fills the dialog from such a file. Nothing changes until you click **Save**.
- A version DNN Manager learned after the file was exported stays on the path.
- A file that isn't an exported path, or has a version that can't be used, is refused with the reason, and the path stays as it was.

### Host project is removed
- The **Host project** page is gone, with its sidebar entry, its command in the command palette and **Ctrl+3**.
- A website comes in through **New project** - **A new site**, or **An existing site** from a `.zip` of its files and its database backup - or through **Clone…** on a project's right-click menu.
- To point a project at another database, use **Change connection…** on its **Database** tab. To put a missing database back, use **Restore backup**.

## Other changes
- While **Update** downloads a new version, a thin bar under the button fills up, and its tooltip gives the percentage.
- Buttons such as **Cancel**, **Close**, **Import…** and the bulk actions above the Projects table have a quieter outline, like the table's. Text boxes, lists and check boxes keep theirs.

## Upgrading
Install over 1.8.4 as usual. Your settings keep their format.
- The versions you added to the upgrade path in 1.8.3 and 1.8.4 work as before: they only add to what DNN Manager knows. Change one in the dialog and save, and your values replace DNN's.
- Projects you set up with **Host project** keep working. A website folder that is already on this PC but isn't in IIS can no longer be set up from DNN Manager: make a `.zip` of its files and a backup of its database, and use **New project → Start from: An existing site**.
- The download bar shows from the next update on. Updating to this version still uses 1.8.4's **Update** button.

## Tested
- All 493 fast automated tests pass, up from 473. New ones cover the edited upgrade path (a version taken off is skipped and the step says so, a lower minimum replaces DNN's, a version added earlier still only raises), exporting and importing it, and files that are refused.
